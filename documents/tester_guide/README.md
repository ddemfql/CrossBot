## 本次确定的操作

- 默认使用管理员账号。W1 问题为“请问你们可以制作纸巾包装盒，并发货到美国加州吗？”。W2 按已核实产品资料生成指定平台文案。两者仍在主工作台 app.py 使用。
- W3 默认直接导入示例 ZIP，使用本目录 zip_workbench.py 启动的独立 ZIP 版工作台。app.py 的当前 W3 单文件上传框仍不接受 ZIP，不能混用入口。
- ZIP 版使用独立的本地管理员账号；首次空账号库创建管理员，密码至少 10 位。主工作台管理员密码至少 12 位，两套账号、Case 和数据不互通；同名账号也需分别创建和登录。此启动文件仅调用现有 w3_app.render，没有另建导入、权限或存储实现。

## 启动 ZIP 版

在仓库根目录的 WSL 环境执行：

~~~sh
export CROSSBOT_W3_DATA="$PWD/.w3-data/tester-guide"
./.venv/bin/python -B -m streamlit run documents/tester_guide/zip_workbench.py --server.address 127.0.0.1 --server.port 8503 --server.headless true --browser.gatherUsageStats false
~~~

打开 [http://127.0.0.1:8503](http://127.0.0.1:8503)。Windows PowerShell 启动命令见 [根 README 第 6 节](../../README.md#6-自检与验收)。上述命令使用隔离测试目录；未设置 CROSSBOT_W3_DATA 时默认写入 ~/.crossbot/w3，不要误用已有业务库。

## ZIP 导入与固定清单

1. 登录 ZIP 版管理员 → 新建交易 / 导入资料 → 导入已有资料 ZIP → 选择原包 → 导入资料。无需解压或预先新建交易。
2. 看到“资料已导入，请核对分类。”；新交易自动选中。相同字节的 ZIP 重复导入返回同一交易。
3. 展开“调整资料与交付清单”，把“设置内容”选为“文件清单”。清空来源后只选下表 12 类；交付只选商业发票 CI、装箱单 PL；点“保存两类清单”。

| 需要提供的资料：界面准确名称 | 本例目录分类文件数 |
| --- | ---: |
| 包装标签内容表 | 3 |
| 其他资料 | 2 |
| 产品规格表 | 1 |
| 形式发票 PI | 2 |
| 买方订单 PO | 2 |
| 生产要求单 | 1 |
| 承运人提单 | 1 |
| 商业发票及装箱合并表 | 1 |
| ISF 资料准备表 | 1 |
| 合规声明填写稿 | 4 |
| 销售合同填写稿 | 1 |
| 出货照片 | 20 |
| 合计 | 39 |

这是本例测试来源分类，不是所有交易的法定必需清单，也不证明合同已签署、合规认证有效或 ISF 已申报。归类来自目录，仍需对照正文人工修正。原件不因被归为填写稿而被覆盖。

4. 文件分类与查看 → 按分类查看 / 查看文件；核对 39 份原件、分类与版本。必要时“修正文件分类 → 保存分类”。只有缺件或修订时才使用单文件补传。
5. 采集并填入表单 / 移除文件 → 采集后填入哪份表单 → CI 或 PL → 采集并填入表单。同一合并表可分别用于 CI 与 PL。候选不自动确认，主订单数据仍需核实。
6. 生成与导出 → 需要生成的文件：先 CI 再 PL。按“审核结果”处理缺项和来源；保存人工补充，逐项核对外部字段及全部产品明细。FAIL / PENDING_REVIEW 不可绕过。
7. 预览当前文件 → 预览文件 → 下载待核对预览。保存全部编辑并通过必需规则后，由真人勾选“我已人工核对当前资料，确认按现有内容生成”，点“确认并生成”，再“下载当前文件”。CI 和 PL 分别完成。
8. 历史版本与多文件打包 → 选择原件与生成文件 → 打包所选文件 → 下载所选文件 ZIP。生成、打包不等于批准、对外发送、已发货或已到账。

## 已验证与限制

- 本例原 ZIP 已在临时数据库实际导入：39 份文件全部保留且原件哈希一致；重复导入不重复建单；12 类来源与 CI/PL 交付配置保存成功。临时副本在测试后删除，没有操作默认业务库。
- 11 份文档产生字段候选，36 份带解析或人工核对提示；这不是自动识别成功率，也不表示真实单据已经审核通过。照片、扫描件、复杂表格及未知字段仍需人工处理。
- ZIP 限制：包 300 MB、单文件 20 MB、解压总量 300 MB、最多 2000 条目；加密、损坏、不安全路径与符号链接拒绝。本例目录与大小检查通过。
- 此前教程验证没有调用真实模型，文字和截图使用隔离合成数据。本次按用户明确授权，将原交易 ZIP 原样放入 examples/ 并随仓库提交；该包未脱敏，其他真实业务数据、账号与密钥仍不提交。
- 29 项合成回归通过；AppTest 与实际浏览器均完成合成 ZIP 表单导入。交互教程的页面检查另见 VERIFICATION.md。

业务文件的准确性、来源确认、模板与最终输出仍须由测试人员逐项验收。原件、候选、人工修改、生成版本及审计记录分别保留。

## 从 test use 上传产品资料、知识库、风险词库

仓库未随附额外的 test use 文件夹；如准备人员另行提供，可按文件名或说明找到三类模板。没有该文件夹时，直接在主工作台对应页面下载产品资料、知识库、风险词库的 JSON 模板即可。空白模板先按核实资料填写，再在主工作台“资料与知识”中分别进入“产品资料”“知识库”“风险词库”。展开对应上传面板，使用“选择产品资料文件 / 选择知识库文件 / 选择风险词库文件”，预览条目、填写“内容来源（必填）”，分别“保存到产品资料草稿 / 保存到知识库草稿 / 保存到风险词库草稿”。

产品资料与风险词库支持JSON/CSV；知识库另支持UTF-8 TXT/Markdown，单文件不超过2MB。多条记录文件每次保存选中一条。保存后提交审核，由另一有审核权限账号审核通过，再由管理员发布。本人（含管理员）不能自审；草稿未发布不能当作生成使用的正式知识。
