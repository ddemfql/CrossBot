## 4. 请 A 评审的结果契约需求

当前 `CrossCheckResult` 已有规则、两侧值、两侧来源字符串及文档 ID，但不能独立表达以下必要证据。请 A 决定最小契约变更，再由 D 同步后实现 `result_builder.py`，本轮不自行加字段。

| 需求 | 评审时需要回答 |
|---|---|
| 两侧版本与来源 | 如何结构化保存各侧版本 ID、字段定位；Case 一侧如何表达确认依据，不能虚构文档 ID 或页码 |
| 规范化证据 | 原值与规范化值、单位换算、容差及规则版本如何共同保存，足以复现当次判断 |
| 明细粒度 | 同一规则对多个商品或单据产生多条结果时，如何区分对应对象并检查是否遗漏 |
| 严重级别与风险 | 必要规则、严重级别、风险对象与结果如何关联；冲突与待复核并存时如何汇总 |
| 输入变化 | 文档新版本、人工确认值变化、规则/策略变化如何使旧结果失效；如何禁止继续用旧 PASS 关闭 Case |

一个用于评审的人工证据例子：规则 IP-004，左侧 `doc-demo-invoice` / `ver-demo-invoice-1`，PDF 第 2 页毛重 `1 kg`；右侧 `doc-demo-packing` / `ver-demo-packing-1`，工作表 `Synthetic` 单元格 `B10` 毛重 `1000 g`。两侧均人工确认、相同装运范围，样例明确零容差，规范化均为 `1 kg`，值级结果 PASS。这个例子需要全部证据可以保存和读回；不能把版本和单位拼进 `left_source` / `right_source` 当隐藏接口。

## 5. 已有状态校验的缺口与验收边界

根据当前 `core/validators.py`，校验器会拦截必需单据缺失、已有字段未确认、必需任务未批准、结果为空或包含非 PASS。新测试已覆盖这些已有行为。

仍需 A/C/D 联调的目标：

1. 核对必要规则和应有明细是否全部产生结果。现在“传入一条 PASS”并不能证明全规则通过。
2. 核对文档、复核任务和比对结果属于同一 Case；D 的新预检仅保护主动调用它的路径，未接入原状态入口。
3. 核对结果来自当前文档版本与当前确认值。当前模型和状态校验不能证明旧结果已失效。
4. 校验必须存在的关键字段及来源证据；不能仅确认当前 `fields` 中已有的字段。

新版本且字段未复核时已有校验能拦截；新版本全部确认但仍携带旧 PASS 时，仍需结果失效机制。不能用前一种测试代替后一种验收。
