# 询盘候选引用定位修复

用户在 V3 第二项验收中提供截图：当前为真实模式，点击识别后显示“格式、字段或原文位置不符”。截图不足以判断具体哪一项校验失败；助手未读取Key、原始HTTP响应或再次调用真实模型。

原方案要求模型返回字符索引。模型可能按不同计数方式、错误偏移或额外字段返回，整批因此被拒绝。修复后主协议只让模型给出允许字段名和逐字原文value，代码在用户本次询盘中计算Python字符位置。

- 只有唯一出现的完整引用才可自动定位，不做大小写、翻译、近似或数值替换。
- 兼容旧版start/end：唯一引用按本地原文重新计算位置；重复引用只有原索引逐字匹配时才接收，不猜选第一处。
- 非法索引类型/负值、重复键/重复项、额外字段、未找到/有歧义的引用仍整批拒绝，失败保留旧候选。
- 错误现在给静态分类原因，不回显原始模型响应；不自动重试、不静默转模拟。
- 所有结果仍为core.ExtractedField的CANDIDATE，confidence/normalized_value保持未知，不自动改数量、国家或Case。

新增回归覆盖Unicode/换行、无索引及错误索引、重复引用、伪造/翻译引用、整批原子失败、提示词和真实模式页面（网络替身）。真实服务修复效果仍需用户本机主动点击验收。
