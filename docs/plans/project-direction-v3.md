# CrossBot 项目方向与落地规划

> 当前版本：V3.0  
> 产品形态：以 Case 为中心的网页业务工作台  
> 第一阶段案例：USB 多档色温桌面台灯出口德国  
> 第一阶段目标：完成附件输入、AI 辅助回复、岗位账号权限、知识库维护和单证核验演示闭环

## 一、产品定位

CrossBot 面向跨境外贸团队，围绕同一个订单 Case，协助客服、产品、运营、单证和复核岗位完成：

```text
客户消息/附件进入 -> AI 识别和字段提取 -> 知识库检索 -> API 生成回复或文案 -> 人工复核 -> Python 规则校验 -> 风险、差异和审计记录
```

系统职责分工：

- AI/API：识别语义、识别图片内容、解析候选字段、模拟客户、生成回复和文案。
- 本地知识库：提供产品、平台、市场和合规依据。
- 网络搜索：当授权数据源无法提供背调时，作为有来源的外部参考。
- Python：执行金额、数量、重量、箱数、币种和状态判断。
- 人工：确认关键字段、审核 AI 输出、发布知识和最终放行。

没有可靠来源的内容必须显示为“待确认”或“外部参考”，不能伪装成确定事实。

## 二、网页应用总体使用方式

### 登录和个人工作台

用户登录后，系统根据账号角色加载岗位权限。所有岗位入口都可见；无权限岗位显示为灰色且不可点击，并说明所需权限。后端必须再次校验每个操作，不能只靠前端按钮控制权限。

### Case 主线

客户消息、图片、PDF、Excel、产品资料、AI 回复、人工修改、复核任务和规则结果统一关联到 Case。

Case 页面包含：概览、客户沟通 W1、产品与 Listing W2、附件与单证 W3、人工复核、交叉比对、知识依据、审计记录。

### 消息来源

第一阶段支持客服粘贴/转述客户消息和上传客户发送的图片、PDF、Excel 等附件。后续可接入邮箱、企业微信、WhatsApp Business、阿里国际站和 CRM Webhook。自动导入后仍进入人工审核队列，不直接自动发送。

## 三、附件输入和识别功能

### 支持格式

| 类型 | 第一阶段处理 | 用途 |
|---|---|---|
| JPG、PNG、WEBP | 图片识别/OCR | 客户聊天截图、产品图片、标签、证书截图 |
| PDF | 文本提取，必要时 OCR | 发票、合同、认证资料、客户附件 |
| XLSX | 工作表、单元格解析 | 报价表、产品参数表、装箱单 |
| CSV | 结构化表格读取 | 批量产品资料、贸易背景数据 |
| DOCX | 后续扩展 | 合同和规格说明 |

W1 和 W3 页面提供粘贴文字、上传图片、上传文件和拖拽附件入口；手机拍照上传列入后续移动端版本。

### 附件处理流程

```text
上传 -> 类型/大小检查 -> SHA-256 -> 保存原文件版本 -> OCR/文本/表格解析 -> AI 提取候选字段 -> 人工确认 -> 写入 Case
```

识别结果区分原始内容、机器提取值、AI 候选值、人工修改值和最终确认值。来源必须可定位：图片页/区域，PDF 页码，Excel 工作表/行/单元格，CSV 行号/列名。

模糊图片、低置信度 OCR、无法读取的 PDF、表头不匹配或不支持的格式一律进入待处理状态，展示原因和需补充内容，不得静默通过。

```text
每箱数量：20 pcs

```

演示附件：

```text
invoice_case_de_lamp_001.pdf
```

## 五、W1 客服工作台

输入客户文字或附件、客户国家、目标语言、客服补充信息及已知产品/订单资料。系统识别询价、认证、交期、付款、物流、售后等意图，并提取数量、国家、港口、认证和单证要求。

之后检索产品/市场知识，调用 API 生成回复草稿，并由本地规则检查绝对化、医疗功效、认证承诺以及无依据的价格和交期。页面输出：

```text
客户可见商务回复
中文风险提示
待确认信息
引用的知识库依据
附件识别结果和来源位置
```

客服可编辑并确认回复，但不能直接修改产品主数据或发布知识库规则；需要修改时提交给产品或管理员岗位。

## 六、W2 产品和运营工作台

### 产品岗位

负责上传图片、规格书、参数表和认证资料；维护产品名称、SKU、材质、尺寸、功率、包装、允许宣传点和需证据支持的功效；提交资料变更审核并查看被哪些 Case 引用。

产品数据至少包含：

```text
product_id, name, sku, specifications, materials, package_info,
allowed_claims, claims_requiring_evidence, certificates, source_files,
version, effective_date, review_status
```

### 运营岗位

负责选择 Amazon、TikTok 或阿里国际站，设置目标市场和语言，生成 Listing、短视频脚本和关键词，处理平台风险并提交发布前复核。只生成用户选择的平台内容；平台为空时不能提交；没有产品依据的参数不能自动补写。

## 七、W3 单证和协同工单

第一阶段支持商业发票 PDF、装箱单 Excel、文本型 PDF、`.xlsx` 固定模板和图片附件。

```text
创建 Case -> 上传附件 -> 本地解析 -> AI 提取候选字段 -> 人工确认 -> Python 交叉比对 -> 通过/失败/待复核
```

Case 状态：

```text
草稿 / 资料待补 / 解析中 / 待复核 / 复核退回 / 交叉比对失败 / 通过 / 关闭
```

| 比对对象 | 字段 |
|---|---|
| 发票 vs 装箱单 | 品名、数量、箱数、毛重、净重 |
| 发票 vs 合同 | 客户、币种、金额、贸易术语 |
| 装箱单 vs 提单 | 件数、重量、收发货人 |
| Case vs 全部单据 | 客户、国家、订单号 |

结果为 `PASS`、`FAIL` 或 `PENDING_REVIEW`。缺字段、低置信度、无法确定或未人工确认时必须待复核；冲突时必须失败。未完成复核或比对的 Case 不能关闭。

## 八、客户背调与网络搜索保底

阿里卖家背调适配器保留，但演示阶段不依赖真实阿里卖家账号。

正式环境可接入阿里授权接口、CRM、企业客户库、邮箱历史记录。演示时授权背调不可用则：

```text
阿里背调不可用 -> 查询 Case/本地客户资料 -> 执行授权网络搜索 -> 展示来源和抓取时间 -> 标记“外部参考” -> 客服人工判断
```

搜索结果必须保留查询词、来源 URL、标题、抓取时间、匹配名称、置信度和复核状态。网络搜索不能自动写入客户主档、判定客户资质或替代人工背调。网络也不可用时使用固定演示资料，并标记“演示数据”。

## 九、账号、岗位和权限

### 账号与角色

第一阶段岗位：管理员、客服、产品专员、运营专员、单证员、复核员。账号可以有多个角色，但只能在获授权的角色之间切换。账号包含 user_id、username、display_name、role_ids、status 和 last_login_at。密码使用安全哈希保存；登录、失败尝试和权限变更写入审计记录。

### 角色切换

页面顶部显示当前角色和全部岗位入口。无权限角色显示灰色、不可点击，并提示“当前账号无此权限”。角色切换只更新该用户允许的菜单与操作；所有 API/服务端操作再次核权。

## 十、知识库和违禁词库维护

有权限的岗位可维护产品参数、客户/市场资料、平台规则、国家沟通规则、认证合规要求、违禁词、多语言同义表达和翻译记忆。

更新流程：

```text
新增/修改 -> 保存草稿 -> 填写来源/版本/生效日期 -> 提交审核 -> 管理员或复核员审批 -> 发布新版本 -> 旧版本归档
```

客服只能提交修改建议；产品专员可维护产品草稿；法规/认证内容必须审核；管理员负责发布和回滚。已发布版本不可覆盖，只能创建新版本。每次检索显示条目版本和来源。

知识条目字段：

```text
knowledge_id, content, category, source, source_url, version,
effective_date, market, platform, product_scope, confidence, status,
created_by, reviewed_by, published_at
```

违禁词字段：

```text
term_id, term, language, pattern_type, severity, platform, market,
replacement_suggestion, source, version, status
```

支持精确词、同义词、正则、多语言表达、平台专属词和“需证据支持”的声明。

## 十一、数据集用途

`china_trade_translation_dataset.csv` 用于外贸中英句式、单证术语和客户模拟语言模板，不能作为产品事实、报价、交期或认证依据。

`trade_i_baci_a_22_2024.csv` 用于国家、HS 编码、产品贸易方向和规模背景。原文件约 1.52 GB，必须离线生成索引；不能证明真实客户、订单、报价、交期或认证。

## 十二、技术架构

第一阶段采用 Streamlit 网页工作台；后续可迁移 React/Vue + FastAPI。

```text
登录页 / Dashboard / Case 列表 / Case 详情
W1 客服 / W2 产品与运营 / W3 单据管理
人工复核 / 知识库管理 / 权限管理 / 审计记录
```

后端模块：

```text
core/                          公共模型、事件、错误、配置、权限契约
workflows/                     W1/W2 和客户模拟
providers/                     API、Mock、网络搜索适配器
knowledge/                     产品库、规则库、检索和版本发布
auth/                          登录、角色和权限
case_workflow/                 Case 和岗位任务
documents/                     图片、PDF、Excel 解析
review/                        人工复核
storage/                       SQLite 持久化
validation/                    Python 规则和交叉比对
```

## 十四、演示脚本

1. 登录客服账号，客服入口可用，产品/复核入口灰显。
2. 进入德国台灯固定 Case，上传客户聊天截图，识别询盘字段。
3. 客服补充目标语言和产品资料，API 生成回复并显示依据、风险和待确认项。
4. 登录产品账号上传产品参数表和图片，提交产品资料。
5. 登录运营账号生成 Amazon/TikTok Listing。
6. 阿里背调无账号时触发网络搜索保底，显示来源并标注“外部参考”；不可联网时显示演示数据。
7. 上传发票 PDF 和装箱单 Excel，展示解析字段来源。
8. 单证员确认字段，Python 比对正常单据显示 `PASS`。
9. 把装箱数量改为 480，显示 `FAIL`；删除净重显示 `PENDING_REVIEW`。
10. 客服尝试关闭 Case 被权限拒绝；复核员完成审核后关闭。
11. 管理员新增违禁词草稿，审核发布新版本并查看审计记录。

## 十五、阶段计划

### 阶段 0：公共基线

公共模型、状态门禁、SQLite、审计和测试完成。

### 阶段 1：网页与账号

登录页、演示账号、岗位权限、灰色无权限角色、Dashboard 和 Case 工作台。

### 阶段 2：W1/W2 与附件

客服粘贴消息、上传图片/PDF/Excel，完成识别；API 回复；网络搜索保底；产品资料维护；平台 Listing 生成。

### 阶段 3：W3 最小闭环

Case、文件哈希/版本、PDF/Excel 解析、来源定位、人工确认、Python 比对和 PASS/FAIL/PENDING_REVIEW。

### 阶段 4：知识库治理

知识/违禁词草稿、权限控制、审核、发布、版本归档和回滚。

### 后续

邮箱/企业微信/WhatsApp/CRM 自动导入，扫描 PDF OCR，更多单证，任务通知，FastAPI+React，私有化部署。

## 十六、第一阶段验收标准

- 用户登录后只能使用授权角色；灰色按钮和后端权限检查都生效。
- 客服可粘贴消息或上传图片/PDF/Excel；原文件、哈希、版本和来源位置均可追溯。
- W1 调用 API 生成回复，风险、知识来源和待确认项可见。
- 阿里背调不可用时使用有来源的网络搜索；搜索不可用时使用明确标记的演示数据。
- 产品岗位可维护产品资料，运营岗位可生成所选平台 Listing。
- 授权用户可编辑知识草稿，审核后发布新版本并可追溯/回滚。
- W3 可解析发票和装箱单，人工复核后运行 Python 交叉比对。
- 未复核、缺字段或比对失败的 Case 不能关闭。
- 正常、冲突、缺失三种演示样例均可运行。
- API 或网络搜索不可用时，W3 本地解析、复核和交叉比对仍可运行。
