# B第三步：W2所选平台与输出范围（模拟）

2026-10-31｜feature/w1-w2-platform。用户已验收W1前两步，本步经批准实施W2模拟平台选择。

## 修改文件和功能

- `workflows/listing.py`：使用公共ListingRequest校验产品描述、所选平台、语言、目标市场和关联ID。按命名JSON字段发送，多行/逗号/引号不拆错。空选、重复、未知平台及错误类型在客户端调用前拒绝。
- 返回仅接受`{"listings":{"平台":"文案"}}`，键集合必须与选择完全一致；缺失、多余、重复JSON键、空文本、错误JSON/封装均拒绝保存。整批原子保存，不显示部分成功伪装的结果。
- `providers/listing_mock.py`：只按所选平台返回明确模拟文案，回显输入、语言、市场与组织提示，不调用模型，不声称完成翻译或语义生成。
- `workflows/listing_ui.py`：所选平台各自展示，空选按钮禁用并提示，改变输入/选择隐藏旧结果；失败保留上次成功批次，但不会把旧平台显示在新选择下。
- `app.py`简化为W1/W2新面板路由，不再使用旧按换行拼接的W2路径；旧main.py及utils等不改写、不删除，保留迁移参考。
- `tests/test_listing.py`8项、`test_listing_ui.py`4项；更新W1切换测试，验证生成W2后返回W1仍保留历史。

## 已知限制

平台提示来自项目自定义`project_style_v1`，明确`official_policy=false`，不是官方最新政策知识。提示进入模型请求，返回后仅检查格式和平台集合；未完成最新平台/目标国规则检索或完整内容合规检查，输出仍要求人工核对。不会把风格提示当成正式平台规则来源。

目前只模拟回显并展示不同组织提示，不验证真实翻译/平台化文案质量。W2暂不支持多轮修改、版本下载或持久化；真实provider与知识来源下一步处理。W1仍可进行已通过的模拟两轮，两个面板会话互相独立。本步无真实模型请求，未commit/push/创建PR。
