# V3 范围、接口依赖与下一批验收

规划来源：[原样保存的 V3.0](plans/project-direction-v3.md)。2026-10-31 初查A为722e56a；提交期间A新增943fc47，仅补两份案例文档，无core/auth契约变动。B已同步该提交并保留A文档原件；仍未发现auth或V3公共接口。以下是建议接口需求，不是已发布契约，也不是已获队长同意的实现决定。

规划要求“公共模型或权限模型变更先由 A 更新，再由其他分支同步”；现有 AI开发约束要求公共契约不足时先提出变更。本分支不擅自修改 core、不复制互不兼容的权限/知识/附件模型，不用页面角色选择代替安全登录。

## A 需先提供的公共契约

1. **身份、授权和审计**：认证后主体、允许角色、当前角色、状态、Case 分配范围；统一权限拒绝错误；由服务端执行的核权接口。明确 W1 回复、客户模拟、附件读取、W2 生成、知识草稿/审核/发布/回滚等操作权限，不能由请求者自报 role 获权。B 接口在读敏感数据或调用模型前检查授权；未认证/未分配/禁用账号都拒绝。
2. **Case 关联的业务请求/输出版本**：在 A 的 SalesRequest/ListingRequest 或另一个公共上下文中明确 case_id、actor_id、产品版本、附件版本引用和已人工确认的字段；生成结果及人工编辑分别保存，来源和审核状态区分。现有 request 的 correlation_id 不是 Case 外键，不把它偷用为 Case ID。
3. **附件读取与识别**：现有 core 的 Document/DocumentVersion/ExtractedField 可复用；需补齐图片页/区域、CSV 行/列、识别方式/错误与 AI 候选/人工原值/最终值的关联。由 C 持久化原件、SHA 和版本，并公开受权读取/解析接口；B 仅消费解析内容做语义识别，不重写 C 的上传/OCR/PDF/XLSX 解析器。无解析器或低质量输出必须待处理。
4. **外部搜索引用**：请 A 定义查询、Case/主体/目的、授权记录，以及结果 URL/标题/抓取时间/名称匹配/置信度/复核状态；区分授权接口、本地资料、外部参考和固定演示。B 再实现搜索供应商适配与保底；不能把生成的网址、模型推测或固定模板包装成已检索网页。实际搜索服务、授权范围和联网配置待确认。
5. **产品及知识版本治理**：产品与知识/词项条目、状态枚举、草稿/审核/发布/归档/回滚版本关系、来源证据、created_by/reviewed_by、published_at；同一主体是否可自审、发布角色矩阵需统一。B 做页面与检索/发布业务，A 提供权限及事务审计/存储接口，D 验证门禁。发布新版本不可覆盖旧版本，回滚通过新发布记录完成。

## 后续 B 工作顺序

A 发布契约与测试后，在 B 分支同步基线；先接 Case/角色核权，再对接 C 附件服务，随后实现搜索适配及知识草稿/审核/发布/回滚。不得通过直接改 JSON 绕过审核，不能将当前 synthetic 条目显示成已发布规则。当前页面仍是 B 独立演示，不是带安全账号的完整工作台。

待集成测试包括：客服不能改主数据/关闭 Case，运营不能发布知识，未分配 Case 拒绝；伪造当前角色拒绝；附件失败保留原件与失败状态；搜索不可用明确显示演示；未审核版本不可被正式检索；回滚保留原版本和审计。W3 本地解析/复核/规则不依赖模型或搜索可用性，由 A/C/D 联调验证。

两份规划没有相同权限细节：知识流程文字允许“管理员或复核员审批”，权限表仅列管理员发布；本分支不自行扩大复核员发布权限，提交 A 统一审批/发布权限。
