# D：单证交叉比对规则清单

文档版本：v0.1；状态：规则设计与评审草案，尚未实现规则引擎。
契约基线：`722e56a`；工作分支：`feature/cross-check-quality`。

## 1. 依据、范围和实现边界

- 开发约束以 [AI开发约束.md](../AI开发约束.md) 为准；目录遵循 [directory-structure.md](directory-structure.md)。
- 模型、枚举和序列化使用 [core/models.py](../core/models.py)；状态流转使用 [core/validators.py](../core/validators.py)，结合 [contracts.md](contracts.md) 阅读。代码中的已有行为与文档中的目标要求分开记录。
- D 的实现目录为 `validation/`、`tests/`；本次仅创建规则文档。已有 `main.py`、`utils/` 等旧实现不作为新功能入口。
- 首批开发 P0：商业发票与装箱单、Case 基础信息与各份适用单据。P1：发票与合同、装箱单与提单；属于规则范围，但启用前需要 C 的字段样例和业务口径。
- 规则使用确定性 Python 逻辑，不调用模型裁决。人工构造样例可先行，不等待完整解析界面；完整 W3 验收需要 C 的解析与复核模块。
- 本清单不新增公共模型、正式字段命名、OCR、上传页面或法规认定功能。公共契约不足时先向 A 提出变更，不用自定义字典或特殊字符串绕过。

## 2. 已有公共契约与待补能力

### 2.1 直接复用的类型

| 用途 | 当前契约 | 使用要求 |
|---|---|---|
| Case 基础信息 | `Case.case_id`、`order_no`、`customer_name`、`destination_country` | Case 字段与单据字段的对应语义需 C 确认 |
| 必需单据 | `Case.required_document_types`、`Document.document_type` | 不凭上传顺序猜测文档类型；同类型多份单据的选择规则需确认 |
| 文档与版本 | `Document.document_id`、`case_id`、`current_version_id`；`DocumentVersion.version_id`、`fields` | 检查归属，使用指定的当前版本，不根据文件名或更新时间猜版本 |
| 字段与来源 | `ExtractedField.name`、`value`、`normalized_value`、`status`、`page_number`、`sheet_name`、`cell_reference` | 来源位置随字段保留；不能假定 `value` 已代表最终人工确认值，其取值约定需 C 明确 |
| 字段复核 | `FieldValueStatus.CONFIRMED` 等 | `CANDIDATE`、`REJECTED`、`MISSING` 不作为已确认字段使用 |
| 比对结果 | `CrossCheckResult` | 使用现有 `rule_code`、`rule_version`、两侧文档/字段/值/来源等字段 |
| 风险 | `RiskItem`、`RiskSeverity.BLOCKING`、`blocking` | 失败或待复核的必要规则建议使用阻断风险；风险与结果的关联方式需 A 确认 |

| 业务显示名称 | 代码枚举 | 序列化值 |
|---|---|---|
| `PASS` | `CrossCheckStatus.PASS` | `pass` |
| `FAIL` | `CrossCheckStatus.FAIL` | `fail` |
| `PENDING_REVIEW` | `CrossCheckStatus.PENDING_REVIEW` | `pending_review` |

正式对象使用枚举，JSON 等序列化使用 `core.models.to_dict`，不把大写显示名称当作枚举值。

### 2.2 当前缺口：作为对接事项，不宣称已经支持

1. `CrossCheckResult` 没有独立的两侧文档版本 ID、规范化值、严重级别或必要规则标记。现有 `left_source` / `right_source` 是来源说明字符串，不能自行塞入特殊格式来代替缺失的结构化契约。由 A 确认最小扩展及风险关联方案。
2. `ExtractedField` 尚无专门的单位、币种、商品行标识、配对关系字段。由 A/C 明确如何用公共契约表达；不能临时约定 `value` 内的匿名结构。
3. 机器原值、人工改值、最终确认值的读取方式，以及 Case 字段自身的确认依据和来源，仍需 C 说明；不能由 D 从 `source` 或 `note` 猜测。
4. 当前状态校验会检查必需单据类型、当前版本及其中已有字段的确认状态；通过/关闭时要求复核任务非空、必需任务已批准、比对结果非空且传入结果全部为 `PASS`。
5. 当前状态校验尚未验证必要规则是否全部产生结果、结果是否属于当前 Case / 当前文档版本，也未列举每种单据必须存在的字段。不能把“传入的一条结果通过”解释为“全部必要规则通过”。完整性、归属和旧结果失效机制需要 A/C/D 联调。

## 3. 共同判定要求

1. 先明确 Case 适用的规则集合和必要规则。P0/P1 是开发顺序，不等于自动启用；缺少适用范围时不得报告全部通过。
2. 已启用的必要规则缺少文档、字段、来源、复核依据或比较口径时返回 `PENDING_REVIEW`。未启用规则记录适用范围说明，不伪造 `PASS`，空结果集合不算通过。
3. 使用同一 Case 的文档和正确版本；总计对总计、明细对已确认配对的明细。不得把单据级重量、箱数按商品行重复累加。
4. 商品需要唯一且已确认的标识或人工配对。行序不同不代表商品不同；重复标识、缺少配对、拆分/合并行口径不明时待复核，不按行号、模糊品名或模型语义自动配对。
5. `PASS`：规则适用，必要输入与复核证据齐全，比较策略明确，满足一致条件。`FAIL`：比较前提明确且确定不一致。`PENDING_REVIEW`：不能可靠判断，必须说明原因。
6. 同时存在失败和待复核时保留全部明细；汇总方式与 A 对齐。首批启用规则是否均为必要规则，待评审确认。
7. 所有必要规则通过只是 Case 通过/关闭的必要条件，其他复核和状态条件仍由公共状态校验及 C 的流程检查。

## 4. 规范化规则

| 类型 | 首版处理要求 | 待复核情况 |
|---|---|---|
| 金额 | 从明确的数值文本解析为 `Decimal`；同时核对币种和金额范围；不使用浮点数作最终比较，不做汇率换算 | 数字分隔符、币种、税费/运费范围、精度或舍入口径不明 |
| 数量 | 保留数值、单位和商品范围；不截断小数，不跨商品直接求和 | 单位、数量合法性、拆分/合并行口径不明 |
| 箱数/件数 | 区分箱、包、托盘和商品件数；整数数值形式可统一，不能把 `10.5` 截为 `10` | 包装层级或装箱系数不明、非整数计数无法解释 |
| 重量 | `Decimal`；先明确支持 `g`、`kg`，按 `1 kg = 1000 g` 精确换算；毛重、净重分开 | 单位缺失或不支持、重量类型/统计范围不明、比较策略缺失 |
| 币种 | 已确认的币种代码统一大小写，别名仅按明确映射处理 | `$` 等有歧义符号或币种缺失，不继承另一侧币种 |
| 日期 | 接受有效的 `YYYY-MM-DD`；其他格式需要明确约定；首版不因此新增日期比对业务规则 | 无效日历日期或 `01/02/2026` 等格式歧义 |
| 单位 | 与数值一起比较；只做明确换算或已确认别名映射 | 无单位不能默认补齐；箱与件没有产品装箱系数时不换算 |
| 文本/标识 | 去除首尾空白，保留有意义的内部字符、标点、前导零；使用已确认标识或映射 | 不自动翻译、改写公司/品名，大小写和别名规则不明时待复核 |

- 区分数值 `0`、空文本、`None` 和格式错误。`NA`、`N/A`、`—` 等文本按契约解释，未约定时保留原值并待复核。
- 零值、负值、小数数量是否合法需要按字段确认；不能让两侧相同的非法值通过。当前 `validate_case` 已禁止负的 `Case.invoice_total`，不得在新规则中放宽。
- 精度、舍入与容差分别确认；不自行加默认误差或四舍五入。缺少业务比较策略时相关规则待复核，纯转换函数仍可独立测试。

## 5. 业务规则目录

以下示例全是人工构造的测试数据。假设共同前提已满足，角色/标识/单位已确认；金额和重量样例显式采用精确比较（容差为 0），不代表生产容差已获批准。每条规则至少准备 `<规则ID>-PASS`、`<规则ID>-FAIL` 两个基础用例，以及适用的缺失和格式异常用例。

### 5.1 P0：商业发票 vs 装箱单

| 规则 ID | 字段与范围 | 通过 / 冲突示例 | 额外待复核条件 |
|---|---|---|---|
| IP-001 | 已配对商品的品名，按约定文本规则比较 | 同一商品标识下，`Desk Lamp` 对 `Desk Lamp` 为通过，对 `Desk Lamp Pro` 为冲突 | 配对、名称别名或语言差异未确认 |
| IP-002 | 已配对商品、相同单位的数量 | `100 pcs` 对 `100 pcs` 为通过，对 `120 pcs` 为冲突 | 单位、拆分/合并行或汇总口径不明 |
| IP-003 | 相同装运范围和包装层级的箱数 | `10 箱` 对 `10 箱` 为通过，对 `12 箱` 为冲突 | 发票是否提供箱数、包装层级或范围未确认 |
| IP-004 | 相同范围的毛重，换算后按确认策略比较 | `10 kg` 对 `10000 g` 为通过，对 `12 kg` 为冲突 | 重量范围、精度、舍入或容差未确认 |
| IP-005 | 相同范围的净重，换算后按确认策略比较 | `8 kg` 对 `8000 g` 为通过，对 `9 kg` 为冲突 | 净重类型不明，或比较策略未确认 |

### 5.2 P0：Case 基础信息 vs 各份适用单据

每份适用单据分别产生结果，不能只检查第一份。Case 侧保留 Case 字段及确认依据，不虚构 PDF 页码。以下字段名仅在 `Case` 侧已确定，单据侧对应的 `ExtractedField.name` 需 C 确认。

| 规则 ID | 字段与范围 | 通过 / 冲突示例 | 额外待复核条件 |
|---|---|---|---|
| CASE-001 | `customer_name` 对相同业务角色的客户 | 已确认的 `Acme Ltd` 对 `Acme Ltd` 为通过，对 `Example Ltd` 为冲突 | 买方、付款方、收货方角色或客户映射不明 |
| CASE-002 | `destination_country` 对目的国 | 已确认国家代码 `DE` 对 `DE` 为通过，对 `FR` 为冲突 | 不得混用原产国、中转国；国家映射不明 |
| CASE-003 | `order_no` 对相同订单范围的订单号 | `PO-001` 对 `PO-001` 为通过，对 `PO-002` 为冲突 | 多订单、前导零、大小写或分隔符口径不明 |

### 5.3 P1：商业发票 vs 合同

启用前确认 `DocumentType.SALES_CONTRACT` 输入、字段及范围，并取得样例；不假定 C 首批解析器已经支持合同。

| 规则 ID | 字段与范围 | 通过 / 冲突示例 | 额外待复核条件 |
|---|---|---|---|
| IC-001 | 相同角色的客户 | 已确认的 `Acme Ltd` 对 `Acme Ltd` 为通过，对 `Example Ltd` 为冲突 | 客户角色或映射不明 |
| IC-002 | 对应金额的币种 | `USD` 对 `USD` 为通过，对 `EUR` 为冲突 | 多币种与金额的对应关系不明 |
| IC-003 | 同一订单/批次、同一口径的金额 | `USD 1000.00` 对 `USD 1000.00` 为通过，对 `USD 1200.00` 为冲突 | 部分发货、税费/运费、折扣、精度或容差不明；币种不同则本条待复核，由 IC-002 报告币种冲突 |
| IC-004 | 贸易条款约定的全部组成项 | 仅在样例明确只比较代码时，`FOB` 对 `FOB` 为通过，对 `CIF` 为冲突 | 实际是否包含指定地点和条款版本需确认，不能将代码相同当作完整条款相同 |

### 5.4 P1：装箱单 vs 提单

启用前确认 `DocumentType.BILL_OF_LADING` 输入、包装和重量含义、收发货人角色，并取得样例。

| 规则 ID | 字段与范围 | 通过 / 冲突示例 | 额外待复核条件 |
|---|---|---|---|
| PB-001 | 同一运输范围、相同包装计数口径的件数 | `10 packages` 对 `10 packages` 为通过，对 `12 packages` 为冲突 | package、carton、pallet、商品件数的关系不明 |
| PB-002 | 同一运输范围、同一重量类型的重量 | 两侧均为总毛重时，`10 kg` 对 `10000 g` 为通过，对 `12 kg` 为冲突 | 未明确类型的 weight 不能直接作为毛重/净重 |
| PB-003 | 相同角色的收货人 | 已确认的 `Consignee A` 对 `Consignee A` 为通过，对 `Consignee B` 为冲突 | 特殊表示、角色或名称映射未确认 |
| PB-004 | 相同角色的发货人 | 已确认的 `Shipper A` 对 `Shipper A` 为通过，对 `Shipper B` 为冲突 | 不直接用卖方代替发货人；角色或映射不明 |

## 7. 对接确认与契约变更清单

| 编号 | 事项 | 对接人 | 确认前 D 的处理 |
|---|---|---|---|
| Q-01 | 单据字段名称、可用范围、同类型多文档选择、必要规则清单 | A + C | 使用标明为合成数据的夹具，不自动启用全部规则 |

| Q-04 | 重复商品、拆分/合并行、箱件换算及单据总计的范围 | C + D | 优先实现明确一对一的场景，不确定则待复核 |
