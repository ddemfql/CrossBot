# 真实工作流

## 入口与资料

工作台只提供真实业务入口。资料与知识下分产品资料、知识库、风险词库，权限与原有发布审核流程继续生效。
上传草稿并不等于已发布；客服生成只读取已发布版本。产品规格、认证、价格及交期没有依据时保留待确认。

## W1 询盘

直接选择“新建询盘”，指定回复语言（决定生成文本语言）和可选产品，粘贴客户消息后生成。
无需先创建订单 Case。询盘按登录账号隔离，消息、回复、修改版本及检索来源保存到 SQLite 的 inquiries 表。
API 失败时客户消息仍保存，使用“重试生成回复”。新的客户消息继续原对话；“调整回复”保存一个新稿。

系统提示要求：礼貌问候、按客户问题回答、询问仍缺少的关键信息。
程序只采用已发布产品检索；多个产品同时命中会要求明确产品，不混合参数。没有产品命中不会由系统补造参数。
订单字段候选须带客户原文引用，程序检查值确实出现在引文中、引文确实属于客户消息。
这可阻止无来源字段进入订单草稿，并不能保证模型对所有语义和事实都判断正确，仍需人工复核。

识别明确下单表达（例如“We confirm the order for 500 lamps.”、“我们确认下单500件台灯。”）后，
与回复在同一事务生成一次订单草稿 Case 并分配给当前客服。
询价、带条件或否定的下单表达不自动建单；订单意图识别采用保守规则，复杂表达可能需要客户进一步明确。
客户名称、目的地未明确时界面显示待确认，metadata 中对应值仍为 null，不作为已确认业务值。
全部候选字段 confirmed=false。创建 Case 不代表正式成交、收款或审核通过。

首次订单草稿为不可自动覆盖的交接快照。后续客户变更继续保存于询盘，工作人员在 Case 中按证据复核变更。
询盘与 Case 并不自动同步到外部电商平台，也不会替客户提交订单。

## W2 营销文案

选择工作 Case、产品、目标平台与语言，通过配置的真实 API 生成或修订文案。
平台规则来自本地保存的官方页面摘要及来源链接，风险扫描还读取已发布风险词库。
词项检测结果表示需要审查，不代表平台完整禁词表，不保证通过平台审核。
产品事实与平台规则分别提供给模型，规则不能充当产品认证证明。

## W3 订单核对

客服通过“前往订单核对”进入已创建 Case。其他岗位由管理员分配相应 Case 后进入。
W1 交接字段是待审核参照。上传平台原始订单后先解析与人工核对，再执行 Python 确定性比对。
文件保存能力、自动解析能力与审核通过状态分别处理；不支持自动识别的文件保留原件并允许人工补录。
缺失字段、未确认字段、未识别字段不算一致，不会自动 PASS。

## 登录和密钥

刷新通过浏览器 cookie 恢复原有服务器会话，每次仍校验账号、角色、会话撤销状态和原始八小时有效期。
退出会撤销服务器会话并删除 cookie。当前 Streamlit JavaScript 组件方式不支持 HttpOnly；公网部署应评估可信组件、HTTPS 与身份网关。

模型设置只保留在当前 Streamlit 页面会话的内存中，不再提供保存配置或记住 API Key，也不调用 Windows DPAPI。
切换 W1/W2/W3 或资料页面时保留当前配置；刷新、新开页面、退出登录或更换账号后重新填写密钥并确认业务发送。
登录 cookie 仍可在刷新后恢复有效登录，这不会恢复 API 配置。业务导出不包含密钥或登录 token。
旧数据库已有的加密配置行保持原样，当前程序不再读取、解密或写入这些行，不自动清理已有数据。
详细行为及验证方式见 [登录与配置](auth-browser-settings.md)。

## 平台规则来源

`knowledge/platform_policies.json` 分开保存来源、采集日、市场和核验状态。
本轮取得可读原文的包括 Amazon 官方商品上架指南的安全合规资料说明与 Alibaba.com 卖家规则的虚假/夸大宣传条款。
Amazon Seller Central 的部分政策页与 TikTok Shop 页面未取得可核验最新正文，明确标记待核验。
当地派生风险模式用于提示核对，不冒充官方完整禁词表。无适用市场规则时提示人工核对，不套用美国规则到其他市场。
