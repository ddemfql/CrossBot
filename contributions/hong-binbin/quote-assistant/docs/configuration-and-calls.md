# 配置与调用说明

本文用于说明应用如何配置、如何调用商品资料和模型，以及结果如何回到界面。操作步骤见[运行与演示说明](runbook.md)；本文对应当前本地代码，不是在线智能体平台的配置截图。

## 1. 配置材料入口

本作品采用自编Python应用，配置主要保存在源码和本地JSON中，没有Dify等平台的工作流导出文件。提交时可提供以下可读快照，并与完整源码一起使用。

| 材料 | 内容与用途 |
|---|---|
| [app-configuration.json](../deliverables/configuration/app-configuration.json) | 当前模型端点、参数、输出结构，以及18个配置／源码／数据文件的SHA256 |
| [生成提示词](../deliverables/configuration/generation-system-prompt.txt) | 从当前源码导出的完整生成指令 |
| [理解修改提示词](../deliverables/configuration/interpretation-system-prompt.txt) | 从当前源码导出的数量／付款提取指令 |
| [生成输入重建示例](../deliverables/configuration/reconstructed-generation-inputs.json) | 使用当前组装函数和V1–V3归档重建的业务请求资料；不是原始HTTP日志 |
| [真实三版结果](verification/demo-two-rounds-history.json) | 用户此前实际调用后下载的草稿、输入、对话要求和检查报告；原文件未改 |

快照仅供审阅，应用不会读取`app-configuration.json`启动；它不是一键导入其他平台的格式。提示词代表导出时的当前代码，不证明早期V1使用了完全相同的提示词。快照没有API Key或会话认证内容。

## 2. 运行、角色与能力配置

| 项目 | 配置位置 | 当前值／职责 |
|---|---|---|
| 启动 | `start-local.cmd` | 运行`local_lab/app.py`，监听`127.0.0.1:8501`，关闭Streamlit使用统计 |
| 交互 | `local_lab/app.py` | 填写需求／检查并生成／修订与下载三个页签 |
| 输入结构 | Pydantic模型与表单 | 商品、数量、拟议付款、场景、模拟买家材质；不是任意文档自动解析 |
| 业务角色输出 | `deepseek_client.py`提示词与`Draft` | 英文客户回复`english_reply`；中文采购／跟单清单`chinese_checklist` |
| 修改理解 | `dialogue.py` | 仅提取数量与付款文字；模糊或不支持的要求转澄清 |
| 商品资料 | `planning/fixtures/products.json` | 本地模拟目录；`catalog.py`读取、校验 |
| 金额 | `quotation.py` | 按数量选择单价档位，用Decimal计算货品金额 |
| 规则资料 | 本地检查模块与`local_lab/rules/` | C01完整性、C02比例、C03英文表述、P01材质对照 |
| 版本 | `revisions.py`与页面会话 | 保存成功版本、原始修改要求、检查报告，导出TXT／JSON |

这是一个应用的两类业务产出，不是两个独立自主智能体。所谓知识依据为本地结构化文件，没有向量检索或自动采集服务。详细来源见[数据与知识说明](data-sources.md)。

## 3. 模型接口

以下是当前代码设置，不表示本轮重新测试了服务可用性。

| 参数 | 理解修改 | 生成两份草稿 |
|---|---|---|
| 触发按钮 | 让 AI 理解修改 | 生成英文回复与中文清单 |
| 入口函数 | `dialogue.interpret_change` | `deepseek_client.generate_draft` |
| 地址 | `https://api.deepseek.com/chat/completions` | 同左 |
| 模型 | `deepseek-flash` | 同左 |
| 请求 | POST JSON，system提示词+user业务JSON | 同左 |
| 输出上限 | 700 tokens | 1800 tokens |
| 输出格式 | `response_format.type=json_object` | 同左 |
| 流式／思考 | `stream=false`，`thinking.type=disabled` | 同左 |
| 超时设置 | 60秒 | 60秒 |
| 响应大小检查 | 超过131072字节拒绝 | 超过262144字节拒绝 |
| 完成状态 | `finish_reason`必须为`stop` | 同左 |

请求认证使用用户在第二栏密码框填写的密钥。未填写或格式无效时在本地停止；密钥不从本文、导出快照或项目配置文件加载。程序拒绝HTTP重定向，无自动重试；没有在代码中配置temperature等其他采样参数。

理解与生成各消耗一次模型请求；预览、应用修改、查价、规则检查、下载和恢复不请求模型。初始生成加两轮理解／生成的成功路径为五次请求，不包括手动重试。

## 4. 工作流一：首次询盘回复

```mermaid
flowchart LR
    A[用户填写模拟询盘] --> B[目录校验与Decimal查价计算]
    B --> C[C01付款完整性 / C02比例 / P01材质]
    C --> D[用户点击生成]
    D --> E[DeepSeek返回英文回复与中文清单]
    E --> F[结构校验与C03英文表述检查]
    F --> G[保存版本 / 人工复核 / 下载]
```

1. 表单提供所选商品、数量、付款与场景。数量必须满足商品MOQ；无有效商品或数量时无法生成。
2. `build_context`组织商品信息、数量、币种、单价、货品金额、付款填写状态、价格范围和未确认事项。价格与金额由程序计算。
3. `request_context`加入C02报告与P01报告，并按普通邮件／RFQ场景设定`workflow`。明确付款比例错误会停用生成按钮；材质不符则保留提示并允许生成说明差异的替代品草稿。
4. 模型接收业务资料和规则结果，返回两段文本；程序读取`choices[0].message.content`并按`Draft`校验。两个字段都须是非空字符串，最多各12000字符，不允许额外字段。
5. C03在生成完成后检查英文原文；它不是首次生成前的模型输入。随后追加版本快照，页面显示两份草稿和检查报告。

结构通过不代表自然语言中的金额、事实或措辞全部正确；金额仍须与程序值人工比对。提示词要求保留模拟标记、待双方确认和材质差异，但不是对模型永不出错的保证。

## 5. 工作流二：对话修订

```mermaid
flowchart LR
    A[中文修改要求与当前报价] --> B[AI提取quantity / payment_terms]
    B --> C[结构与可应用性检查]
    C --> D[程序重新取价计算并展示差异]
    D --> E[用户确认应用]
    E --> F[回到第二栏另行生成]
    F --> G[保存原始要求 / 新版草稿 / 报告]
```

理解请求的user资料包含`current`（当前商品、金额和付款上下文）及`request`（用户本轮原话）。当前理解面板不传完整RFQ报告，它只处理数量和付款；RFQ场景与材质在后续生成环节另行加入。

返回的`ChangeProposal`结构：

| 字段 | 含义与约束 |
|---|---|
| `quantity` | 整数1～1000000或null；null表示不修改，严格拒绝字符串／布尔值替代整数 |
| `payment_terms` | 最多500字符的字符串或null；null不修改，空字符串表示清除 |
| `clarification` | 最多1000字符，需澄清时填写；无则空串 |
| `unsupported` | 不支持的修改清单，最多10项；无则空数组 |

存在澄清问题、不支持项、无变化或重新计算失败时，不出现可应用的有效修改。对“数量保持／维持N个”与当前数量不符的有限句式，程序在发请求前拦截；不是所有自然语言矛盾都能检测。

确认应用只改变表单中的数量／付款并暂存原始要求与差异，不自动生成草稿。用户再次点击生成后，模型资料包含当前事实、`dialogue`、C02／P01报告，以及`revision.previous_version`、`previous_facts`和`changes`。这里发送的是上一版业务上下文，不是整段历史聊天或上一版英文草稿。

## 6. 已完成的一次调用链及两轮迭代

证据来源：[三版导出](verification/demo-two-rounds-history.json)与[人工核对记录](verification/demo-two-rounds-review.md)。下表按该归档说明结果，不重新调用模型。

| 阶段 | 触发输入 | 程序结果 | 返回与界面反馈 |
|---|---|---|---|
| V1首次生成 | BAG-001，500个，拟议50%/50%；RFQ要求涤纶，商品棉布 | 单价1.20，货品金额600 USD | 英文客户草稿、中文清单；材质差异提示；保存V1 |
| V2第一轮 | 数量改成1000个，付款条件不变。 | 切换单价档位至1.05，金额1050 USD | 预览数量／单价／金额三项变化；确认生成后保存原话与V2 |
| V3第二轮 | 付款改为拟议30%预付、70%发货前，待双方确认；数量保持1000个 | 数量、单价、金额不变 | 仅付款字段变化；英文与中文保留材质差异和双方待确认；保存V3 |

最终报告：C02 `consistent`、C03 `manual`、P01 `mismatch`。C02/C03属于同一合同条款相关类别；P01是有限的平台规则参考，不是平台审核通过。V3中文对C02曾使用不精确的“完整性规则”称呼，实际职责以代码中的算术检查为准，归档原文未改。

两轮原始修改要求保存在`context.dialogue.user_message`，字段差异保存在`feedback`。中途曾重启并恢复第一轮备份后继续第二轮；三版证据连续，不声称现场运行全程没有中断。

没有保存原始HTTP响应、服务端request ID、实际token用量或耗时日志；不能用业务导出推导这些数据。请求重建示例明确标注`Offline reconstruction`，用于展示当前函数如何组装已保存资料，不冒充当时逐字节发出的请求。

## 7. 状态、异常与恢复

| 条件／状态 | 应用行为 | 用户下一步 |
|---|---|---|
| 商品文件损坏或无效数量 | 提示错误，无有效上下文，不允许生成 | 修复目录或输入 |
| C02明确比例错误 | 生成按钮停用 | 修改付款比例并重新核对 |
| P01材质不同／未知 | 展示差异或人工核对提示，不当作自动拒绝交易 | 人工核实需求；草稿须保留差异 |
| 理解失败／需澄清 | 不应用新报价事实 | 修改请求或人工核对 |
| 请求HTTP错误、超时、返回截断／格式不符 | 显示静态错误，不自动重试；失败生成不新增版本 | 检查网络、密钥或额度后决定是否手动重试 |
| 当前输入变化 | 当前草稿失效，历史版本仍保留并标注对应旧输入 | 为新输入另行生成 |
| C03未命中风险短语 | 仍为人工审核范围，不自动批准 | 阅读完整草稿 |
| 刷新／重启导致空历史 | 不保证自动找回 | 使用已下载备份；固定恢复按运行说明操作 |

`quote_history`保存深拷贝版本；`pending_change`保存理解预览；`applied_dialogue`保存用户已确认的要求；`ai_draft`保存当前草稿。密钥是独立会话字段，不进入导出。

恢复功能只支持两份固定、SHA核验的原V1和第一轮V1/V2；恢复第一轮会替换当前输入与历史，旧历史暂存在会话供下载。最新V3已有文件备份，但没有通用导入、数据库或自动持久保存。完整操作见[运行说明第6节](runbook.md#6-下载与恢复)。

## 8. 重建配置材料

在项目根目录运行：

```powershell
& '.\.venv\Scripts\python.exe' tools/export_app_configuration.py
```

脚本读取当前源代码、Pydantic结构和指定模拟演示归档，生成四份审阅文件；不访问用户页面、读取会话密钥或发起网络请求。它不会更改原始演示JSON。调整代码后应重新导出并复核配置说明。

本轮核对记录见[配置材料检查](verification/configuration-and-calls-review.md)。赛事提交时仍需保留完整源码、依赖锁定文件、规则／商品JSON和其他交付材料；这些审阅快照不替代完整工程。
